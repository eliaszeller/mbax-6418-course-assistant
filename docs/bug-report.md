# MBAX 6418 Course Assistant — Development Bug Report

This report consolidates the defects identified while building and reviewing the course assistant. Each issue records reproducible steps, expected behavior, actual behavior, root cause, resolution, and verification status.

## Bug 1: Missing-information fallback raises a validation error

### Steps to reproduce

1. Create a `CourseAssistant` with at least one valid course chunk.
2. Use a test client whose response cites an unknown source ID, such as `{"answer":"Invented","sources":[{"source_id":"missing"}]}`.
3. Ask a question unsupported by the indexed material, such as “Who won the 2034 World Cup?”
4. Observe the error-handling path after citation validation fails.

### Expected behavior

The app should return “A verifiable answer was not found in the selected course materials,” with no sources. It should remain usable and must not invent an answer or citation.

### Actual behavior

The original fallback said “The course materials did not provide a verifiable answer.” The `Answer` validator permitted an empty source list only when the response contained the exact phrase `not found`, so Pydantic raised a second `ValidationError` while handling the first validation failure.

### Root cause and fix

The fallback and validator used inconsistent wording rules. The fallback now explicitly contains `not found`, satisfying the validator and communicating that the evidence is insufficient.

### Verification

`CoreTests.test_missing_information_returns_grounded_fallback` supplies an invalid source ID and verifies that no exception is raised, sources remain empty, and the response contains `not found`.

## Bug 2: Hero text has insufficient color contrast

### Steps to reproduce

1. Start the app and open its Gradio URL.
2. View the hero banner in the light or dark browser theme.
3. Compare the course title and statistic labels with the charcoal background.

### Expected behavior

The title should be high-contrast off-white, labels should be a readable neutral gray, and the school name should retain the Leeds-inspired gold accent.

### Actual behavior

Gradio’s theme rules rendered the title and labels in dark navy on a charcoal gradient. The adjacent introduction and numeric values remained light, making the mismatch especially visible.

### Root cause and fix

The custom CSS colored only the parent `.hero`; more-specific Gradio component rules overrode nested headings and spans. Scoped selectors now explicitly apply `#f8fafc` to the title and values, `#e7e5e4` to supporting copy, `#d6d3d1` to labels, and `#fbbf24` to the school name.

### Verification

The corrected banner was visually inspected in the relaunched public Gradio interface. All hero text is now readable and consistent with the charcoal, off-white, and Leeds-gold palette.

## Bug 3: Study-scope metrics remain static

### Steps to reproduce

1. Launch the app with all four lecture decks selected.
2. Clear one or more checkboxes under **Course materials**.
3. Observe the hero banner.
4. Add or remove a material and observe the banner again.

### Expected behavior

The banner should reflect the active scope immediately. The number of lecture decks, unique slides/pages, and searchable records should change when selections change and after materials are added or removed. Singular and plural labels should remain grammatically correct.

### Actual behavior

The banner always displayed `4 lecture decks`, `125 slides`, and `250 text and visual records`, regardless of the selected materials. This could mislead students about which content was being searched.

### Root cause and fix

The hero was a static HTML string with hard-coded totals. It is now generated by `scope_summary()`, which filters the live library by selected material, counts unique material/locator pairs, and counts scoped searchable records. The selection, upload, and removal events all refresh the hero component.

### Verification

Automated tests continue to pass. Manual verification confirmed that deselecting Week 3 changed the banner immediately from `4 lecture decks / 125 slides/pages / 250 searchable records` to `3 lecture decks / 92 slides/pages / 184 searchable records`. The same event path is used after additions and removals.

## Regression command

```bash
python -m unittest discover -s tests -v
```

## Overall status

All three bugs are fixed. The automated test suite passes, and the two visual/interface fixes have been checked in the running Gradio application.
